# กฎการตัด Rough Cut (ภาษาไทย)

กฎชุดนี้มาจาก skill `noobit-vdo-editor` (ส่วนการตัดคำพูด) และ `noobit-short-editor` (ส่วนเลือกเนื้อหาให้พอดีความยาว)
ปรับจากการที่ผู้ใช้จริงแก้งานของ AI มาหลายคลิป อ่านทั้งไฟล์ก่อนเลือกจุดตัดครับ

## 1. สิ่งที่ต้องเก็บไว้ (ห้ามตัด)

คำลงท้ายและคำเชื่อมที่ทำให้เสียงพูดเป็นธรรมชาติ **เก็บไว้ทั้งหมด**:
นะครับ / ครับ / ค่ะ / เนี่ย / แล้วก็ (ที่เชื่อมรายการกลางประโยค) / คือ / เนอะ / นั่นเอง

- อย่าตัดคำแบบกว้างๆ เช่น ตัด "คือ" ทุกตัว ประโยคจะขาดและฟังแข็ง
- อย่าตัดจนกิน "นะครับ" ท้ายประโยคก่อนหน้า
- ความเห็นส่วนตัวสั้นๆ (< 4 วิ) เช่น "พอดีผมเพิ่งไปอ่านหนังสือเล่มนี้มา" เก็บไว้ ทำให้คลิปมีชีวิต
- ช่วงเงียบที่จอกำลังโชว์ผลลัพธ์ (เช่น ผู้พูดบอก "ดูนี่ครับ" แล้วเงียบให้ดูวิดีโอที่ AI สร้าง) ห้ามตัด
  ใส่ `{"from": a, "to": b, "keep": true}` ใน edits.json

## 2. ช่วงเงียบ (สคริปต์ตัดให้เองอัตโนมัติ)

| profile | ใช้กับ | ตัดเงียบที่ยาวกว่า | เว้นไว้ก่อน/หลังเสียงพูด |
|---|---|---|---|
| `tight` (ค่าเริ่มต้น) | คลิปสั้น, อัดหน้าจอสอน | 0.18 วิ | 0.03 / 0.04 วิ |
| `relaxed` | พูดหน้ากล้องแบบสบายๆ | 0.40 วิ | 0.05 / 0.08 วิ |

ไม่ต้องเขียนรายการตัดช่วงเงียบเอง ส่วนเสียงสั้นๆ ที่ไม่ใช่คำ (อื้ม, หายใจ, เสียงปาก) ที่อยู่ระหว่างช่วงเงียบ `build` ก็ตัดให้เอง

## 3. ตัดคำพูดผิด (หน้าที่ของ AI: อ่าน transcript แล้วเขียนลง edits.json)

### 3.1 พูดผิดแล้วพูดใหม่ (retake): เก็บรอบสุดท้ายที่พูดจบสมบูรณ์
- ตัดจาก **ท้ายส่วนที่สองรอบพูดเหมือนกัน** ไปจนถึง **ท้ายช่วงเงียบก่อนรอบใหม่**
- **ห้าม** เอาครึ่งแรกของรอบ 1 ไปต่อกับครึ่งหลังของรอบ 2 (จะได้ยินน้ำเสียงกระโดด)
- ถ้าพูดซ้ำ 3 รอบ ตัด 2 รอบแรกทิ้งทั้งหมด รวมถึงคำที่พูดค้างไว้

### 3.2 พูดค้าง / เริ่มประโยคแล้วเลิก (false start)
- "วิธีสร้าง… วิธีการสร้าง Template จัดการสต็อก" → ตัด "วิธีสร้าง…"
- "แล้วก็ทำการ…" (พูดค้างแล้วรอ) → ตัดทั้งวลีพร้อมช่วงรอ

### 3.3 คำซ้ำเล็กๆ กลางประโยค
- "จนไปถึงงานที่… จนไปถึงงานที่ช่วยเรา", "แต่พอผม แต่ผมคิดว่า", "ก็คือจะเป็น ก็คือจะเป็น"
- whisper มัก **รวบคำซ้ำ** ทำให้มองไม่เห็นใน transcript → ตรงไหนที่คำเชื่อมซ้อนกันแปลกๆ (ซึ่ง/แต่/แล้วก็ ติดกัน) หรือ transcript อ่านไม่เป็นภาษา
  ให้ใช้ `spot CLIP a b` ช่วงสั้น 2–4 วิ ฟังซ้ำ จะเห็นคำซ้ำที่ transcript หลักไม่เห็น
- ถ้าพูดติดแล้วหาจุดตัดสะอาดไม่ได้ → ถอยไปตัดทั้งวลีตั้งแต่ขอบประโยคก่อนหน้า ยอมเสียเนื้อหานิดหน่อยดีกว่าปล่อยไว้

### 3.4 เสียงอึกอัก
- "เอ่อ" "อืม" "อ่า" ที่ใช้คั่น ("ก็จะเป็น อ่า ร้านเครื่องดื่ม") → ตัด
- "อ่า นี่ครับ" ที่ไม่มีเนื้อหา → ตัด

### 3.5 คำติดปากขึ้นต้นวลี "ซึ่ง" / "แล้วก็"
- **ตัด** เมื่อขึ้นต้นวลีใหม่ (หลังช่วงเงียบ หรือหลัง ครับ/นะ/เนอะ/นั่นเอง) และตัดแล้วประโยคยังสมบูรณ์
  "…นั่นเองครับ **ซึ่ง**วิธีการเริ่มต้นใช้งาน…" → "…นั่นเองครับ วิธีการเริ่มต้นใช้งาน…"
- **ไม่ตัด** เมื่อเป็นคำเชื่อมกลางประโยคจริง ("Google Drive แล้วก็ Google Calendar", "สกิลซึ่งเอาไว้สำหรับ…")
- ใช้ `fillers --verify --emit cand.json` ให้สคริปต์หาตำแหน่งจากระดับเสียงแล้วถอดเสียงยืนยัน จากนั้น **อ่าน ctx ทุกบรรทัด** ลบอันที่ประโยคต้องใช้คำนั้น แล้วค่อยรวมเข้า edits.json
- ตัดแค่ "แล้ว" เหลือ "ก็" ก็ฟังเป็นธรรมชาติได้

### 3.6 คำบอกลำดับซ้ำ
- "อันดับแรกเดี๋ยวผมขอพาไปดู… / **อันดับแรกครับ** ในเคสแรก" → ตัดอันที่สอง

## 4. ทำให้ไม่เกินความยาวที่ผู้ใช้ต้องการ

หลังเขียนการตัดคำผิดแล้ว สั่ง `estimate` ถ้ายังยาวเกินเป้าหมาย ต้องตัด **เนื้อหาทั้งก้อน** เพิ่ม เรียงตามลำดับนี้ (ตัดข้อบนก่อน):

1. **ช่วงรอ** AI/หน้าเว็บโหลด, เลื่อนจอโดยไม่พูด
2. **ประโยคเล่าสภาพการอัด**: "เดี๋ยวผมกดทิ้งไว้นะครับ", "อันนี้ผมต่อไว้แล้วนะ", "เดี๋ยวผมพาไปดูในแต่ละตัวเลยครับ"
3. **พูดซ้ำความหมาย** (ไม่ใช่ซ้ำคำ): ทิปที่พูดไปแล้ว, สรุปสิ่งที่เพิ่งทำ, ประโยคเกริ่นที่ไม่มีเนื้อหา ("แต่ว่าสิ่งนี้ได้เปลี่ยนไปแล้วนะครับ")
4. **บรรยายสิ่งที่จอโชว์อยู่แล้ว**: "ระบบก็จะให้เราเลือกบัญชีนะครับ" (ตอนจอเป็นหน้าเลือกบัญชี)
5. **คำอธิบายที่ผู้พูดไม่มั่นใจ / เดา**, ความเห็นยาวๆ, บ่น
6. **ตัวอย่างยาว / รายการแจกแจง**: เก็บแค่หัวข้อ
7. **ขั้นตอนที่ไม่จำเป็นต่อผลลัพธ์**: ตัดทั้งขั้น (เช่น ตั้งค่าที่เป็นค่าเริ่มต้นอยู่แล้ว)

ต้องคงโครงเรื่องไว้เสมอ: **เปิด (ปัญหา/ผลลัพธ์) → สิ่งนี้คืออะไร → ขั้นตอน → ผลลัพธ์ → ปิดสั้นๆ**
ถ้าตัดตามลำดับข้างบนหมดแล้วยังเกิน **อย่าตัดขั้นตอนหลักทิ้ง** ให้บอกผู้ใช้ว่าความยาวต่ำสุดที่ยังรู้เรื่องคือเท่าไร แล้วถามว่าจะยอมเกินหรือให้ตัดส่วนไหน

ทุกก้อนเนื้อหาที่ตัดเพื่อลดความยาว ใส่ `"note"` ให้ชัด (ผู้ใช้จะเห็นในรายงาน และเอากลับมาเองใน CapCut ได้)

## 5. หาจุดตัดให้แม่น

- เวลาของคำใน transcript/`words` **ช้ากว่าจริง ~0.3 วิ**
- เลือกจุดตัดด้วย `dip CLIP a:b` เท่านั้น (ค่าเฉลี่ย 3 เฟรม) **ห้าม** เลือกจากเฟรมเงียบเฟรมเดียว เคยตัดโดนคำ "โอเค" มาแล้ว
  - `CLEAN` (< −40 dB) = ตัดได้สบาย
  - `weak` / `none` = ไม่มีช่องเงียบ → ใช้ `fit CLIP FROM TO --tail "คำก่อนตัด" --head "คำหลังตัด"` ให้สคริปต์ลองหลายจุดแล้วถอดเสียงยืนยัน และใส่ `"check": 1`
- คำที่ขึ้นต้นด้วย ซ/ส/ฟ/ฉ/ห เสียงต้นคำเบามาก `dip` อาจหลอก → ขยับ `from` เร็วขึ้น ~0.15 วิ แล้วเช็กใน qa
- ตัด retake: `to` = ท้ายช่วงเงียบก่อนรอบใหม่ (หาได้จาก `[pause a-b]` ใน `words`)
- ไม่แน่ใจตรงไหน ใส่ `"check": 1` (จะขึ้นในรายงานให้ผู้ใช้ไปฟัง)

## 6. รูปแบบ edits.json

```json
{
 "profiles": {"my-clip": "tight"},
 "edits": {"my-clip": [
   {"from": 31.90, "to": 35.58, "note": "พูดซ้ำ 'วิธีการสร้าง…' เก็บรอบหลัง"},
   {"from": 10.25, "to": 10.95, "note": "ตัดคำติดปาก 'ซึ่ง' ต้นวลี", "check": 1},
   {"from": 90.80, "to": 123.70, "note": "รอ AI สร้างไฟล์ (ตัดเพื่อให้ไม่เกิน 3 นาที)"},
   {"from": 230.0, "to": 238.5, "keep": true}
 ]}
}
```

- เวลาเป็น **วินาทีในไฟล์วิดีโอต้นฉบับ** (ไม่ใช่เวลาใน timeline)
- ชื่อคลิป (`my-clip`) ดูได้จากชื่อไฟล์ transcript ในโฟลเดอร์ work
- `note` เขียนเป็นภาษาไทย ผู้ใช้จะอ่านในรายงาน

## 7. อ่านผล qa

- ทุกจุดตัดจะมีบรรทัด `edge: …ท้ายก่อนตัด ‖ หัวหลังตัด…`
  **ท้ายต้องจบวลี และหัวต้องขึ้นวลีใหม่** ถ้าเห็นคำโผล่มาครึ่งเดียว ("ผม", "ที่", "สรุป") ให้ขยับ from/to ไปที่ pause ก่อนหน้า/ถัดไป
- คำเพี้ยนหรือคำขาด (เช่น "ค่อนข้างอก") ในช่วง 6 วิ = ไม่ผ่าน แม้ edge จะดูปกติ → ถอยไปตัดที่ขอบวลี
- `⚠ head opens with 'ซึ่ง'` → ตัดคำนั้นด้วยถ้าประโยคยังสมบูรณ์
- `dup?` = คำซ้ำตรงรอยต่อ ("แล้ว ‖ แล้ว") → ขยับจุดตัดไปที่ช่วงเงียบก่อนคำที่ซ้ำ
- สถิติช่วงเงียบ: `tight` ควรได้ median ≈ 0.10–0.13 วิ, p95 ≤ 0.20 วิ
- แก้ edits.json → `build --overwrite` → `qa` อีกรอบ จนผ่าน
